1. Executive Summary & Modern Problem Formulation

Modern enterprise computing is overwhelmingly multi-cloud. According to industry analyses by Gartner and Flexera, over 89% of enterprise organizations maintain infrastructure simultaneously across Amazon Web Services (AWS), Microsoft Azure, and Google Cloud Platform (GCP). However, cloud financial management (FinOps) remains critically fragmented: between 30% and 35% of enterprise cloud expenditure represents entirely preventable infrastructure waste. This leakage arises from abandoned storage volumes, zombie virtual machines idling under 5% CPU utilization, unassociated public IPv4 addresses, and continuous off-hours execution of dev/test environments.

Historically, cloud engineers have resisted automated cleanup tools due to the Blind Automation Dilemma: naive scripts delete or terminate cloud assets based solely on utilization thresholds without analyzing the operational blast radius. Deleting an unattached database backup volume, or stopping a production web server positioned behind an application load balancer, causes severe service outages. As a result, engineering leads routinely disable automated cleanup scripts, allowing financial waste to compound unchecked.

The CloudOptima Solution & Core Value Proposition
CloudOptima bridges this gap through a 7-layer governed pipeline. By ingesting official FOCUS 1.0 multi-cloud billing datasets and Azure Public Dataset 5-minute VM CPU traces, CloudOptima pairs deterministic heuristic rules with Isolation Forest machine learning. Crucially, every remediation action is evaluated by an Explainable Multi-Factor Risk Classifier (scoring Environment, Topology, Action, and Confidence). High-risk assets are held in a Human Governance Approver Queue, and every mutation is guarded by mandatory pre-action snapshot creation, post-action verification, and fail-safe 1-click rollback.

3. Multi-Cloud Billing Data: FOCUS 1.0 Standard & Public Datasets

A foundational challenge in multi-cloud FinOps is billing data taxonomy fragmentation. AWS Cost and Usage Reports (CUR), Azure Cost Management exports, and Google Cloud Billing CSVs use completely incompatible column names, date encodings, and charge categories. To resolve this, CloudOptima adopts the official FinOps Open Cost and Usage Specification (FOCUS) Version 1.0, established by the FinOps Foundation.

4. Utilization Data: Azure Public Dataset VM Traces

While billing line items provide historical spend, they lack the high-frequency temporal granularity needed to reliably identify idle and oversized resources without triggering false alarms. CloudOptima integrates real virtual machine traces from the Azure Public Dataset (https://github.com/Azure/AzurePublicDataset), providing 5-minute CPU utilization readings across enterprise VM fleets.

Mathematical Idle VM Detection Criteria (azure_traces.py)
A compute instance is flagged as an idle_instance if and only if:
Avg_CPU_7d = (1 / N) * SUM(avg_cpu_i) < 10.0% AND P95_CPU_7d < 20.0%
Where N = 2,016 five-minute intervals across 7 days. If P95_CPU exceeds 20.0%, the instance is classified as "Bursty / Periodic Batch" rather than genuinely idle, preventing catastrophic false-positive terminations.

5. Synthetic Leak Injection & Academic Benchmark Methodology

To objectively validate detection accuracy without jeopardizing proprietary enterprise data, CloudOptima implements a controlled Synthetic Leak Injection Engine. Real billing and trace distributions are augmented with carefully labeled synthetic anomalies mimicking common cloud anti-patterns. Each record contains ground truth labels (is_synthetic_leak: bool, ground_truth_leak_type: string) against which the dual detection engine is rigorously evaluated.

6. Layer 5: Multi-Factor Risk Classifier (Core Academic Contribution)

The primary academic and engineering novelty of CloudOptima is the Multi-Factor Risk Classifier. Rather than treating all waste equally, the classifier scores operational blast radius using a mathematically bounded 0–100 objective evaluation function across four weighted dimensions:

Risk Classifier Mathematical Formulation
Risk Score = min(100, Score_Env + Score_Topology + Score_Action + Score_Confidence)

• Score_Env (40% Weight, Max 45 pts): Production (+45), Staging (+20), Dev/Test (+5), Untagged (+25)
• Score_Topology (30% Weight, Max 35 pts): Behind Load Balancer (+35), Active Disk Mounts (+25), Standalone (0)
• Score_Action (20% Weight, Max 20 pts): Volume Deletion (+20), Instance Stop (+15), IP Release (+5)
• Score_Confidence (10% Weight, Max 10 pts): Boundary Metric (8-10% CPU) (+10), Definitive 0-IOPS (-5)
Risk Category Score Range Execution Routing Operational Safety Mandate
LOW RISK0.0 – 34.9Auto-Remediation QueueZero-touch execution if auto-remediation flag is enabled on cloud account. Example: orphaned dev volume.
MEDIUM RISK35.0 – 69.9Human Approval QueueEnqueued for review by DevOps/FinOps lead. Displays risk factor breakdown and blast radius context.
HIGH / CRITICAL70.0 – 100.0Critical Governance QueueCritical alert; strictly enforces mandatory pre-action snapshot backup and human authorization before execution.

8. Conclusion & Future Roadmap

CloudOptima demonstrates that automated multi-cloud waste reduction is achievable without sacrificing operational safety or provoking engineering pushback. By grounding automated waste detection in the official FOCUS 1.0 standard, validating against real Azure Public Dataset traces, and governing all remediation actions through an explainable Multi-Factor Risk Classifier, enterprises can confidently auto-remediate low-risk waste while maintaining ironclad human governance over mission-critical production workloads.
